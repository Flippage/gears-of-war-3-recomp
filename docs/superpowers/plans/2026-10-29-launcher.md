# Launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `launcher.exe` that sets the game up from the player's own ISO, Title Update 6 and DLC, swaps the right prebuilt build in as `gow3.exe`, edits `gow3.toml` with the F10 options, and offers new GitHub releases. `gow3.exe` hands over to it when setup is needed.

**Architecture:** A static library `gow3_setup` (no rex runtime; plain C++23 plus Win32) holds everything testable: XEX/STFS/XDVDFS readers, the finder, `launcher.ini` state, the launch decision, install steps, version compare, JSON scan and settings literals. The game links it for its start-up check. `launcher.exe` links it plus `rex::runtime`, for ImGui 1.92.5 (already inside the runtime), `rex::filesystem` and the key names, and draws with the Win32 and DX11 ImGui backends. `gow3_setup_tests.exe` links only the library.

**Tech Stack:** C++23, clang-cl/lld (scripts/build.ps1), CMake + Ninja, Dear ImGui 1.92.5 (from rexruntime; backends from the SDK's `thirdparty/imgui`), toml++ (`rex::tomlplusplus`), WinHTTP, BCrypt, IFileOpenDialog, Windows `tar.exe` for zip extraction.

**Spec:** `docs/superpowers/specs/2026-10-29-launcher-design.md`

## Global Constraints

- Never ship, upload, download or commit any game, title update or DLC file. Tests build fixtures in memory; real-file tests read paths from environment variables and are skipped when they're unset.
- Never delete or change saves, the ISO or the player's packages. The launcher writes only the chosen game folder, `<game>\TU6`, `<game>\DLC` and its own files next to itself.
- Never touch `%LOCALAPPDATA%` in tests. Temporary files go under `<build>\test-tmp`.
- File names: `gow3.exe`, `launcher.exe`, `builds\gow3-base.exe`, `builds\gow3-tu6.exe`, `gow3.toml`, `gow3_game_path.txt`, `launcher.ini`, `version.txt`, `launcher.old.exe`, `gow3.exe.new`.
- `launcher.ini` keys: `build = base|tu6`, `declined`, `installed` (comma-separated package ids), `skip_release`, `check_updates = true|false`, `last_check` (Unix seconds, for once a day). A package id is `<file name>:<size in bytes>`.
- Gears of War 3 title ID `4D5308AB`. TU content type `000B0000`, DLC content type `00000002`. STFS magic: `CON `, `LIVE`, `PIRS`.
- Release API: `https://api.github.com/repos/Flippage/gears-of-war-3-recomp/releases/latest`. Asset `gow3-recomp-<version>-win64.zip` plus `.sha256`. The zip's top folder is `gow3-recomp-<version>-win64\`. Tag `v<version>`.
- The update never replaces `gow3.toml`, `gow3_game_path.txt` or `launcher.ini`.
- No DLSS in releases: the upscaler list drops `dlss` when `nvngx_dlss.dll` is missing (the catalog already does this). Keep it that way.
- Colours: background #0E0F11, sidebar #121417, panels #15171A, lines #1C1F23, text #D7D9DC, muted #7B8088, accent #D23B3B, success #5FBF7A. Teko (`assets/fonts/Teko-Variable.ttf`) for headings.
- Window 900 x 560, fixed size, borderless, with its own title bar.
- Version source: `package.ps1 -Version` writes `version.txt` (one line, e.g. `0.3.0`) next to `launcher.exe`. The launcher reads it. With no `version.txt` (dev build), update checks are skipped. This is how the plan implements the spec's "launcher's own version (from the packaging version)", without recompiling for each release.
- Do not play the game or drive it. Steps that launch the game are run by the user.
- Commits: author `Flippage <10948118+Flippage@users.noreply.github.com>`, on branch `tu6-dlc`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.

## Review Focus

1. **`gow3.toml` that toml++ can't parse** (a hand edit with a typo). Expect a message saying the settings tabs are read-only; the file is never written. Test in Task 9.
2. **`gow3.exe` still running** when a swap or an update starts (Play pressed twice, a game left open). Expect a wait of up to 30 s, then "Close the game first", with `gow3.exe` untouched, never missing or half-written. Test in Task 7.
3. **Non-ASCII paths** (`D:\Spiele\Gears of War 3 – Kopie\`, a Cyrillic user name). Expect finder, extract and the path file to work. All paths stay `std::filesystem::path` (wide); the path file is UTF-8 read via `u8path`. Tests in Tasks 3 and 5.
4. **Big or unrelated files in scanned folders** (the 7.6 GB ISO next to the packages, `.zip` files, locked files, folders with access denied). Expect the package scan to read at most the first 0x1000 bytes of a file and skip errors silently. Tests in Tasks 4 and 6.
5. **Stale `gow3_game_path.txt`** (drive unplugged, folder moved). Expect `gow3.exe` to open `launcher.exe --setup`; no crash and no MessageBox loop. Test in Task 8.

### Task 5: XDVDFS disc image reader

**Files:** Create `setup/xdvdfs.{h,cpp}`, `tests/xdvdfs_test.cpp`

**Interfaces:**
- Produces:
```cpp
struct DiscEntry { std::string path; uint64_t offset; uint64_t size; bool dir; };   // path uses '\'
class DiscImage {
 public:
  static std::optional<DiscImage> Open(const std::filesystem::path& iso, std::string* error);
  const std::vector<DiscEntry>& Entries() const;
  uint64_t TotalBytes() const;                                   // sum of file sizes
  std::optional<std::vector<uint8_t>> ReadFile(std::string_view path, size_t max_bytes) const;
  ExtractResult ExtractAll(const std::filesystem::path& out_dir, const Progress& progress,
                           std::string* error) const;            // ExtractResult, Progress from stfs.h
};
```
- Partition offsets to probe, in order: `0` (xiso from extract-xiso), `0x2080000` (XGD3), `0xFD90000` (XGD2), `0x18300000` (XGD1). The volume descriptor is at `partition + 0x10000`: magic `MICROSOFT*XBOX*MEDIA` (20 bytes), root dir sector `Le32(+20)`, root dir size `Le32(+24)`. Sector size 2048; an absolute sector offset is `partition + sector * 2048`.
- Directory entry (little-endian): `left u16, right u16` (in 4-byte units from the dir start; 0 = none), `sector u32, size u32, attrib u8 (0x10 = dir), name_len u8, name`. Walk the tree from entry 0 with an explicit stack. Skip `0xFFFF` padding. Reject cycles, so a corrupt image can't loop.
- `ExtractAll` writes `<file>.part` and then renames it. It copies in 4 MiB chunks and calls `progress` after each chunk. Files that already exist with the same size are overwritten (spec: running it again overwrites).

### Task 6: Finder

**Files:** Create `setup/finder.{h,cpp}`, `tests/finder_test.cpp`

**Interfaces:**
- Consumes: `ReadXexInfoFile`, `ReadStfsHeader`, `DiscImage::Open`/`ReadFile`, `ReadXexInfo`, `PackageId`.
- Produces:
```cpp
inline constexpr uint32_t kGow3TitleId = 0x4D5308AB, kTuType = 0x000B0000, kDlcType = 0x00000002;
bool IsGameFolder(const std::filesystem::path& dir);       // default.xex file + GearGame dir
std::vector<std::filesystem::path> SearchRoots(const std::filesystem::path& start, int parents);  // start, then up to `parents` parents
struct FoundIso { std::filesystem::path file; uint64_t size; XexInfo xex; };
struct FoundPackage { std::filesystem::path file; uint64_t size; std::string id; StfsHeader header;
                      bool is_tu; bool matches_disc; };
struct FindResult { std::optional<std::filesystem::path> game; std::vector<FoundIso> isos; };
FindResult FindGame(const std::vector<std::filesystem::path>& roots);   // each root and its direct subfolders
std::vector<FoundPackage> FindPackages(const std::vector<std::filesystem::path>& roots, uint32_t disc_media_id);
```
- `FindGame` checks each root, then its direct subfolders. `.iso` files (case-insensitive) count as candidate ISOs only if `default.xex` inside has title `4D5308AB`. Wrong-title ISOs are left out.
- `FindPackages` checks the direct files of each root and of each root's direct subfolders. It skips files under 0x1000 bytes and extensions `.iso .zip .7z .rar .exe .dll .txt .xex .xexp`. It keeps headers with title `4D5308AB` and type TU or DLC. `matches_disc` is `media_id == disc_media_id` for a TU, and always true for DLC. Paths are de-duplicated by `std::filesystem::weakly_canonical`. Every iterator uses `skip_permission_denied` plus `error_code`.
- Search roots: for the launcher it's `SearchRoots(exe_dir, 2)`. For packages it's those plus `game` and `game.parent_path()`.
